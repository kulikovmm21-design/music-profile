# Музыкальный профиль — парсер экспорта Spotify

Первая рабочая часть проекта: берёт архив данных, который Spotify присылает по запросу,
и считает объективную статистику (слой A). Результат — `profile.json`, который потом
получит LLM, чтобы написать текст карточки.

Только стандартная библиотека Python 3.10+, ничего устанавливать не нужно.

## Запуск

```bash
cd music_profile
python3 -m spotify_profile ~/Downloads/my_spotify_data.zip --tz Europe/Moscow --aliases aliases.json
```
(на Windows вместо `python3` пиши `python`)

Архив распаковывать не обязательно: подходит и ZIP целиком, и распакованная папка.
Если программа ругается на часовой пояс (бывает на Windows), выполни один раз `pip install tzdata`
(без него часы будут посчитаны в UTC — программа предупредит).

Полезные параметры: `--out файл.json`, `--recent-days 30` (окно «сейчас»), `--top 20`, `--quiet`.

### Попробовать на демо-данных

```bash
python3 tools/make_demo_export.py demo_export.zip
python3 -m spotify_profile demo_export.zip --tz Europe/Moscow --aliases aliases.json
```

В демо-архиве все артисты **вымышленные**, он нужен только для проверки кода.

### Тесты

```bash
python3 -m unittest discover -s tests
```

## Лаборатория профиля (панель)

Открой `lab/index.html` двойным щелчком. Сервер не нужен, интернет тоже
(без него просто подставятся системные шрифты). Архив разбирается в браузере и никуда не отправляется.

В панели две страницы, переключаются кнопками вверху:
- **Обзор** — для обычного пользователя: любимые артисты и треки, что слушаешь сейчас,
  когда слушаешь, музыка по месяцам. Только понятные цифры и слова.
- **Для продвинутых** (`index.html#advanced`) — настройки расчёта, факты для LLM,
  все цифры смены вкуса, пропуски, плейлисты, качество данных и JSON.

Архив загружается один раз и виден на обеих страницах. Настройки с продвинутой страницы
меняют цифры и в «Обзоре».

Что где править (после правки — обнови страницу, Cmd+R):

| Файл | Что внутри |
|---|---|
| `lab/config.js` | **начни отсюда**: значения по умолчанию, псевдонимы, пороги, часовые пояса |
| `lab/styles.css` | вид: все цвета в блоке `:root` в самом начале, шрифты, отступы |
| `lab/view-simple.js` | страница «Обзор» |
| `lab/view-advanced.js` | страница «Для продвинутых» |
| `lab/app.js` | загрузка архива, переключение страниц, общие функции |
| `lab/core.js` | расчёты — копия Python-логики на JavaScript |
| `lab/demo-data.js` | демо-архив, генерируется сборкой — руками не править |
| `lab/vendor/jszip.min.js` | библиотека чтения ZIP (MIT), лежит локально, чтобы работало офлайн |

Правило: если меняешь расчёт в `core.js`, поменяй то же в `spotify_profile/stats.py`
и запусти проверку совпадения (нужен Node.js и `npm i jszip@3.10.1`):

```bash
python3 tools/make_demo_export.py demo.zip
python3 -m spotify_profile demo.zip --tz Europe/Moscow --aliases aliases.json --out py.json --quiet
node lab/parity_test.js demo.zip py.json aliases.json Europe/Moscow
```

`python3 lab/build.py` обновляет `demo-data.js` и собирает `lab/dist/profile_lab.html` —
всю панель в одном файле, чтобы отправить кому-то. Для обычной работы сборка не нужна.

## Какие файлы архива мы читаем

Справочник — `spotify_profile/catalog.py` (его копия — `FILE_CATALOG` в `lab/core.js`, меняй вместе).
Решение принимается по имени файла **до** чтения:

| Группа | Файлы | Что делаем |
|---|---|---|
| Используем | `StreamingHistory_*`, `Streaming_History_Audio_*`, `Playlist*`, `YourLibrary` | статистика прослушиваний; подкасты и аудиокниги только считаем |
| Используем | `Marquee`, `Wrapped<год>`, `YourSoundCapsule` | выводы самого Spotify: уровни фанатства, итоги года, последние недели (`spotify_profile/extras.py`) |
| Личные | `UserAddress`, `Payments`, `Identity`, `Identifiers`, `UserAttributes`, `MessageData`, `SearchQueries`, `Inferences`, `Follow` | **не открываем вообще** |
| Служебные | `Read_Me_First.pdf`, `iDJAudio`, `AgentGateway` | пропускаем |

Особенности данных Spotify, которые стоит помнить:
- в `Wrapped` артисты, треки и жанры записаны кодами без названий — трек года ищем по коду в твоих плейлистах и лайках;
- в `YourSoundCapsule` число прослушиваний за неделю всегда 0 — берём время (`secondsPlayed`);
- «ночь» в итогах года Spotify считает по-своему, поэтому цифра не совпадает с нашей (00–06).

Мусор macOS (`__MACOSX/`, `._*`) при пересжатии архива на Mac пропускается молча.

## Что считается

| Блок | Что внутри |
|---|---|
| `history.totals` | прослушивания, часы, число артистов и треков |
| `history.top_artists / top_tracks / top_albums` | топы с долями и часами |
| `history.concentration` | доля топ-1 и топ-5, HHI, эффективное число артистов, разнообразие |
| `history.recent_vs_all_time` | «сейчас» против «всего времени»: кто растёт, кто уходит |
| `history.time_habits` | часы и дни недели (в твоём часовом поясе), утро/день/вечер/ночь |
| `history.by_month` | динамика по месяцам, лидер месяца, новые артисты |
| `history.skips` | доля пропусков, самые и наименее пропускаемые артисты |
| `playlists` | состав каждого плейлиста, лидеры, концентрация |
| `facts` | готовые проверенные утверждения с числами — основа для текста LLM |
| `metadata_coverage`, `warnings`, `limitations` | чего в данных нет и чему не доверять |

## Принятые решения (чтобы контекст пережил смену чата)

- **Источник данных для MVP — экспорт Spotify, а не Web API.** С 2026 года API в режиме
  разработки ограничен 5 пользователями и требует Premium у владельца; audio-features
  недоступны новым приложениям с ноября 2024; содержимое чужих плейлистов API не отдаёт.
- **Прослушивание засчитывается от 30 секунд** (как у Spotify). Время — по всем записям.
- **Расширенная история приоритетнее упрощённой**: они пересекаются за последний год,
  при наличии обеих берётся только расширенная.
- **Тип файла определяется по содержимому**, а не по имени — имена в архиве меняются.
- **Псевдонимы артистов склеиваются** через `aliases.json` (пример: Yung Lean = jonatan leandoer96).
  Позже — автоматически через MusicBrainz.
- **Подкасты исключаются** из музыкальной статистики, но их количество сохраняется.
- **Код считает, LLM только пересказывает.** В профиль не попадают выдуманные поля:
  жанров, годов выпуска и аудиопризнаков в экспорте нет — их покрытие честно равно 0.

## Структура

```
spotify_profile/
  models.py    единые модели (Play, Playlist...) — общие для любых будущих источников
  parser.py    адаптер: экспорт Spotify → модели
  aliases.py   склейка псевдонимов
  stats.py     вся статистика и факты
  cli.py       командная строка
tools/make_demo_export.py   генератор демо-архива
tests/                      тесты
```

## Приватность

Архив Spotify содержит личные данные (в том числе IP-адреса и поисковые запросы).
Парсер читает только музыкальные поля; IP, страна и поисковые запросы в `profile.json` не попадают.
Не коммить настоящие архивы и `profile.json` в публичный репозиторий — см. `.gitignore`.

## Следующие шаги

1. Прогнать на настоящем архиве и сверить с тем, что ты помнишь о своих прослушиваниях.
2. Обогатить артистов жанрами/тегами (Last.fm, MusicBrainz).
3. Написать промпт для LLM, который делает карточку только из `profile.json`.
